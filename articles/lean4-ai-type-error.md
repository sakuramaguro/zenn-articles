Leanで赤いエラーが出たとき、その文だけをAIに貼って「直してください」と頼みたくなります。ところが、エラーから分かるのは「Leanが何を受け付けなかったか」です。「何を実現したかったか」までは書かれていません。同じエラーでも、目的によって必要な修正は変わります。

相談するときにそろえたいのは、**再現可能なコード・エラー全文・数学的意図**の3つです。この記事では「自然数に5を足す」という一つの例を使い、質問の作り方から修正後の確認までをたどります。Leanを実行できる環境があれば、Mathlibを追加せずに試せます。

## まず、小さな型エラーを再現する

次を `Failure.lean` というファイルに保存します。これは意図的に失敗するコードです。

```lean
def add_five (n : Nat) : Nat := n + 5

#eval add_five "hello"
```

`Nat` は自然数の型です。最初の行は「自然数 `n` を受け取り、自然数 `n + 5` を返す関数」を定義しています。`#eval` は式の値を計算する命令ですが、ここでは引数に文字列の `"hello"` を渡しています。

Lean 4.29.0-rc6で `lean Failure.lean` を実行すると、次のエラーが出ます。省略していない実行出力です。エディタでは位置情報などの表示が異なる場合があります。

```text
Failure.lean:3:15: error: Application type mismatch: The argument
  "hello"
has type
  String
but is expected to have type
  Nat
in the application
  add_five "hello"
```

長い英語を一度に訳す必要はありません。この例では、次の対応を見ます。

| 表示 | 読み取れること |
| --- | --- |
| `Application type mismatch` | 関数に渡す引数の型が合っていない |
| `"hello"` / `has type String` | 渡した値は文字列 |
| `expected to have type Nat` | この場所で必要なのは自然数 |
| `in the application` 以下 | 問題が起きたのは `add_five "hello"` |

食い違っているのは、引数の `String` と `Nat` です。ただし、ここから「文字列を自然数に置き換えるべき」とまでは決まりません。文字列を数として読み取りたかった可能性もあるからです。

## 質問に添える3つの情報

### 1. 同じエラーが出る最小コード

今回なら、先ほどの3行をそのまま渡せます。追加の `import` や仮定は不要です。`#eval` の行だけでは、相手は `add_five` がどんな関数なのか確認できません。

長い証明なら、必要な `import`、使っている定義、変数、仮定、定理の宣言と証明を残します。別のファイルに切り出して実行し、**相談したいエラーが同じように出るか**を確かめてください。短くする途中で「名前が見つからない」という別のエラーに変わったら、削りすぎです。

最小化は、行数を競う作業ではありません。無関係な部分を減らしつつ、相手が手元で状況を再現できる範囲を残す作業です。仮定を省くと、証明したい命題そのものが変わることもあります。

### 2. エラー全文。証明なら現在のゴールも

`type mismatch` という見出しだけでなく、対象の値、実際の型、期待する型を含めてコピーします。今回なら上の出力全体です。自分が重要だと思った行だけにすると、原因を読む手掛かりを落とすことがあります。

証明の途中なら、その場所の変数・仮定と、`⊢` の後に表示される「これから示すべき命題」も添えます。複数のゴールがある場合は、それらも残します。今回の例は関数の評価なので、証明のゴールはありません。

### 3. 数学的意図と期待する結果

今回は「自然数 `n` に5を足したい。入力7なら12を得たい」と書きます。「`Nat` にしてほしい」だけより、変更してよい範囲が明確になります。

一方、「文字列で届いた数字を読み取り、5を足したい」なら、文字列を自然数へ解析する処理が必要です。その場合は、`"hello"` のように数字でない入力をどう扱うかも決めます。単に引数を7へ変えるだけでは、その目的を満たしません。

証明でも同じです。「この型に合わせたい」に加えて、「どの仮定から、何を示したいか」を自然な言葉で伝えます。エラーを消すために仮定を強くしたり、結論を弱くしたりしてよいとは限りません。

## この例なら、こう質問する

次はコピーして使える記入例です。実際のAIとの会話の引用ではありません。

````text
Lean 4の型エラーの原因と、意図を保つ最小限の修正を教えてください。

【再現コード：Failure.lean】
```lean
def add_five (n : Nat) : Nat := n + 5

#eval add_five "hello"
```

【エラー全文】
```text
Failure.lean:3:15: error: Application type mismatch: The argument
  "hello"
has type
  String
but is expected to have type
  Nat
in the application
  add_five "hello"
```
現在のゴール：なし（証明ではなく #eval でのエラーです）。

【数学的意図・期待する結果】
自然数 n に5を足す関数を使いたいです。入力7なら12を期待します。
文字列を解析する処理は不要です。関数の Nat → Nat という型と、
どの自然数 n に対しても n + 5 を返す目的を保ってください。

【補足】
Lean：4.29.0-rc6。Mathlib：このコードでは使っていません。
試したこと：上のコードを別ファイルに保存して実行し、エラーを再現しました。

修正箇所と理由、修正後の確認方法を示してください。
証明の仮定・結論を勝手に変えず、変更が必要なら理由を説明してください。
未確認の補題名を存在すると断定せず、確認方法も示してください。
````

LeanやMathlibの版、試したことは補足情報です。Mathlibを使う質問なら、プロジェクトの `lean-toolchain` にあるLeanの版と、`lake-manifest.json` のMathlibの `rev` も添えます。分からない欄は推測で埋めず、「未確認」と書けば十分です。

## 修正を受け取ったら、目的に戻って確認する

今回の意図なら、関数の定義を変える必要はありません。渡す値を自然数の7に直します。次を別ファイル `Fixed.lean` に保存します。失敗例の下へ追記すると同じ名前の定義が重なるので、混ぜずに実行してください。

```lean
def add_five (n : Nat) : Nat := n + 5

#check add_five
#eval add_five 7
#eval add_five 0
#eval add_five 100

example (n : Nat) : add_five n = n + 5 := by
  rfl
```

同じ環境で `lean Fixed.lean` を実行した出力は次のとおりです。エラー・警告なしで終了しました。

```text
add_five (n : Nat) : Nat
12
5
105
```

確認は、次の順に行えます。

1. **実行する。** 提案されたコード全体を、必要な前提とともに動かします。説明文で「動く」と書かれていても、手元の結果を確認します。
2. **型を照合する。** `#check` の出力から、自然数を受け取り自然数を返すことを確かめます。補題を提案された場合も、名前が解決できるか、どんな仮定と結論を持つかを確認します。
3. **数学的意図を照合する。** 7で12、0で5、100で105になっています。さらに定義が `n + 5` のままであることを読みます。

いくつかの計算結果だけでは、すべての自然数について正しいとは言えません。最後の `example` は「任意の自然数 `n` に対して `add_five n = n + 5`」を検査する証明です。今回は関数の定義を展開すると両辺が一致するので、`rfl` で証明できます。

**`#check` は名前と型の確認であり、意図どおりの証明完成を保証する命令ではありません。** 証明の修正なら、元の仮定と結論が保たれているか、`sorry` などの未証明部分を残していないかも確認します。3点をそろえるのは診断を助けるためであり、AIの回答の正しさを保証するためではありません。

## 手元の問題に使うテンプレート

次に止まったときは、この空欄を埋めて使えます。新しいエラーが出たら、修正後のコードと新しい出力に更新して相談します。

```text
Lean 4のエラーの原因と、意図を保つ修正を教えてください。

【再現可能な最小コード】
（必要なimport・定義・変数・仮定を含むコードを貼る）

【エラー全文】
（省略せずに貼る）

【現在のゴール：証明の場合】
（その場所の変数・仮定・すべてのゴールを貼る。該当しなければ「なし」）

【数学的意図・期待する結果】
（どの対象に何をしたいか／どの仮定から何を示したいか）
（具体的な入力と期待値、変えてはいけない条件）

【補足】
Leanの版：
Mathlibの版・rev（使う場合）：
試したことと、その結果：

修正箇所・理由・確認方法を示してください。
証明の仮定・結論を勝手に変えず、変更が必要なら理由を説明してください。
未確認の補題名を存在すると断定せず、確認方法も示してください。
```
