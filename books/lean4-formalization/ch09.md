## 9.1 完備性の動機 ──── $\mathbb{Q}$ の「穴」を体感する

### 有理数列の不思議な失敗

次の数列を考えます。$\sqrt{2}$ の小数展開を途中で打ち切った有理数列です。

$$
a_1 = 1,\quad a_2 = 1.4,\quad a_3 = 1.41,\quad a_4 = 1.414,\quad \ldots
$$

小数展開を十分な桁数まで取ると、それ以降の**任意の2項**の差が一様に小さくなります。この意味でCauchy列です。隣り合う項の差が0へ近づくことだけでは不十分で、例えば調和級数の部分和はその条件を満たしてもCauchy列ではありません。しかし $\mathbb{Q}$（有理数）の世界に閉じて考えると、この数列の**極限が存在しません**。$\sqrt{2}$ は有理数ではないからです。

「どんどん近づいているのに、行き先がない」——これが完備でない空間の病理です。

![実数の完備性と、平方根2へ近づく有理数列の対比](/images/vol2/fig-11.png)
*図9-1：実数ではCauchy列が実数へ収束します。有理数では、実数としての極限が有理数に属さないCauchy列が存在します。*

以下では、この議論に関係する距離構造・埋め込み・無理性の定理を確認します。

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

#check (inferInstance : MetricSpace ℚ)
#check Rat.isDenseEmbedding_coe_real
#check irrational_sqrt_two
-- ここでは距離構造・ℝへの稠密な埋め込み・√2の無理性を確認する。
-- インスタンス探索の失敗だけでは ¬ CompleteSpace ℚ の証明にはならない。
```

:::message
**💡 探索の失敗と否定の証明は別**

`inferInstance : CompleteSpace ℚ` の探索失敗だけでは、`¬ CompleteSpace ℚ` を証明したことにはなりません。失敗にはインポートや仮定の不足という原因もあり得ます。有理数の非完備性は、上のCauchy列が有理数の極限を持たないことから数学的に示します。掲載の `#check` は、その議論全体を形式化した証明ではありません。

一方、完備性を仮定する定理を適用するときには、`CompleteSpace X` の証拠が必要です。これは、完備性を根拠なしに利用していないかをLeanが検査する仕組みです。
:::

### なぜ $\mathbb{R}$ は完備なのか

実数にはDedekind切断やCauchy列の同値類など、同等の構成があります。固定したMathlibの `Real` は、有理数のCauchy列を用いる構成です。$\mathbb{R}$ での任意の Cauchy 列は必ず実数の極限を持ちます。

## 9.2 Cauchy 列の定義 ──── 数学⇔Lean対応の確認

### 数学の定義：ε-N 論法

距離空間 $(X, d)$ の数列 $(a_n)_{n \in \mathbb{N}}$ が **Cauchy 列（Cauchy sequence）** であるとは：

$$
\forall \varepsilon > 0,\; \exists N \in \mathbb{N},\; \forall m, n \geq N,\; d(a_m, a_n) < \varepsilon
$$

「$N$ 番目以降の任意の2項の距離が $\varepsilon$ 未満」——「行き先を知らなくても、項が互いに近づいている」という条件です。

Cauchy性は、十分先の項どうしが近いという条件です。極限の候補を指定せずに述べられる点に注目してください。

### Leanの実装：`CauchySeq`

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

#print CauchySeq
#check @Metric.cauchySeq_iff
-- 本章では添字をℕとする。定義自体は前順序を持つ添字型にも使える。
-- CauchySeq u は Cauchy (Filter.map u Filter.atTop) と定義される。
```

数学の定義と Lean の対応を表にまとめます。

| 数学の表現 | Lean の表現 |
|-----------|------------|
| $(a_n)$ は Cauchy 列 | `CauchySeq a` |
| $\forall \varepsilon > 0, \exists N, \forall m,n \geq N, d(a_m,a_n) < \varepsilon$ | `∀ ε > 0, ∃ N, ∀ m ≥ N, ∀ n ≥ N, dist (a m) (a n) < ε` |
| 上の同値 | `Metric.cauchySeq_iff` |
| Cauchy 列の収束（完備空間） | `cauchySeq_tendsto_of_complete` |

次の宣言と `exact` のブロックを順に連結してください。

```lean:完成例・確認コマンド

open Filter Topology

    ∃ N, ∀ m ≥ N, ∀ n ≥ N, dist (a m) (a n) < ε := by
```

**ステップ①：ゴール確認**

```text

hε : 0 < ε
⊢ ∃ N, ∀ m ≥ N, ∀ n ≥ N, dist (a m) (a n) < ε
```



`Metric.cauchySeq_iff.mp` に渡すのは `ha : CauchySeq a` という証明です。続けて `ε` と正値性の証明 `hε` を渡すと、対応する末尾の条件が得られます。

## 9.3 `Cauchy` ──── フィルターのCauchy性

[第6章](ch06)で、数列の収束を `Filter.map a Filter.atTop` の収束として表しました。Cauchy性も同じ像フィルターを使って定義できます。

### 距離空間での2条件

フィルター $\mathcal{F}$ がCauchyであるとは、次の2条件が成り立つことです。

$$
\text{（C1）}\quad \emptyset\notin\mathcal{F}\quad\text{（同値に }\mathcal{F}\ne\bot\text{）}
$$

$$
\text{（C2）}\quad \forall\varepsilon>0,\ \exists S\in\mathcal{F},\
\forall x\in S,\ \forall y\in S,\ d(x,y)<\varepsilon
$$

C1は「集合族として空でない」ことではありません。フィルターは全体集合を必ず含み、ボトムフィルターも空の族ではありません。`⊥` は空集合を含むため、実際にはすべての集合を含むフィルターです。`S=∅` とすればC2は空虚に成り立つので、C1によってそれを除外します。Leanでは `Filter.NeBot` を使います。

### 一様構造による定義

MathlibはCauchy性を、一様空間（`UniformSpace`）の言葉で定義します。距離空間の一様構造では、

$$
E_\varepsilon=\{(x,y)\mid d(x,y)<\varepsilon\}\quad(\varepsilon>0)
$$

を含む集合が **近縁（entourage）** となります。その族を一様性フィルター $\mathcal{U}_X$ と書くと、C2は

$$
\mathcal{F}\times\mathcal{F}\leq\mathcal{U}_X
$$

と言い換えられます。これは、一様性フィルターの各集合が積フィルターにも属するという意味です。距離空間では、対角線の周囲に全点で共通の幅 $\varepsilon$ を持つ集合を使います。**積位相における対角集合の任意の近傍と、一様構造の近縁は同じ概念ではありません。**

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

open scoped Uniformity

#print Cauchy
#check @Metric.cauchy_iff

theorem cauchy_filter_definition (f : Filter ℝ) :
    Cauchy f ↔ f.NeBot ∧ f ×ˢ f ≤ uniformity ℝ := Iff.rfl
```

実際の名前はルート名前空間の `Cauchy` です。定義の第1成分が `f.NeBot`、第2成分が積フィルターと一様性の順序関係です。`Metric.cauchy_iff` で、上のC1・C2へ変換できます。

### 数列との接続

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

theorem cauchy_sequence_definition (a : ℕ → ℝ) :
    CauchySeq a ↔ Cauchy (Filter.map a Filter.atTop) := by
  rfl
```

`CauchySeq a` は、定義により `Cauchy (Filter.map a Filter.atTop)` です。この同値は `rfl` で証明でき、距離空間に限らず一様空間でも使えます。列のCauchy性に極限の候補は登場しません。

## 9.4 `CompleteSpace` 型クラス ──── 免許証の解剖

### 数学の定義：完備距離空間

距離空間 $(X, d)$ が **完備（complete）** であるとは：

$$
(a_n) \text{ が Cauchy 列} \Rightarrow \exists L \in X,\; \lim_{n \to \infty} a_n = L
$$

「すべての Cauchy 列が収束先を $X$ の中に持つ」という条件です。

### Leanの実装：`CompleteSpace`

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

#print CompleteSpace
#check @CompleteSpace.complete
-- [UniformSpace α] の下で、すべてのCauchyフィルターが収束するという条件。
```

:::message
**💡 `CompleteSpace` の定義はフィルターの言語**

`CompleteSpace` の完備性条件は「任意の Cauchy **フィルター** $f$ に対して、ある点 $x$ が存在して $f \leq \mathtt{nhds}\; x$」という形で定義されています。

この定義は一様空間全般で使えます。距離空間では「すべてのCauchy列が収束する」という完備性と同値です。なお、`CauchySeq u` と `Cauchy (map u atTop)` の定義的な一致だけで、この2つの完備性の同値が証明できるわけではありません。後者には、距離による可算な近傍の基底を使います。
:::

### 主要な完備空間のインスタンス

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

#check (inferInstance : CompleteSpace ℝ)
#check (inferInstance : CompleteSpace ℂ)
-- 実・複素ノルム空間に完備性が加わるとBanach空間になる。
```

通常の距離・ノルムを入れた各空間の完備性を表にまとめます。

| 空間 | `MetricSpace` | `CompleteSpace` | 備考 |
|------|:---:|:---:|------|
| $\mathbb{Q}$（有理数） | ✅ | ❌ | $\sqrt{2}$ の穴がある |
| $\mathbb{R}$（実数） | ✅ | ✅ | 有理数のCauchy列による構成 |
| $\mathbb{C}$（複素数） | ✅ | ✅ | $\mathbb{R}^2$ と同型 |
| $\mathbb{R}^n$（有限次元） | ✅ | ✅ | Heine-Borel も成立 |
| $\ell^2$（無限次元） | ✅ | ✅ | Heine-Borel は**不成立** |
| $C([0,1])$（連続関数空間） | ✅ | ✅ | sup ノルムで完備 |

### 手動で展開する：`calc` による距離の評価

次は具体的な等比数列 $(1/2)^n$ を、距離の評価からCauchy列と証明します。この計算自体は完備性を使いません。最後に実数の完備性を適用して極限の存在を得ますが、ここでは極限が0であることまでは示しません。

宣言・`apply`・`intro` と `obtain`・最後の `refine` と `calc` の4つのLeanブロックを順に連結してください。

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

theorem geometric_cauchy : CauchySeq (fun n : ℕ => (1 / 2 : ℝ) ^ n) := by
```

**ステップ①：`Metric.cauchySeq_iff.mpr` でゴール変換**

```lean:断片
  apply Metric.cauchySeq_iff.mpr
```

```text
⊢ ∀ ε > 0, ∃ N, ∀ m ≥ N, ∀ n ≥ N, dist ((1/2)^m) ((1/2)^n) < ε
```

**ステップ②：ε を導入し、`ε/2` を仕込んで N を構成する**

ここが形式証明の「泥臭い」要所です。最終的に示す不等式は `dist (a m) (a n) < ε` ですが、`calc` の終盤で `(1/2)^N + (1/2)^N` という和が現れます。これを `ε` 未満に抑えるには、最初から `ε/2` に対応する `N` を取っておく必要があります。「ゴールから逆算して最初に仕込む」——これが形式証明のリアルな手触りです。

```lean:断片
  intro ε hε
  -- まず ε/2 > 0 を確保する
  have h_half : 0 < ε / 2 := half_pos hε
  -- (1/2)^N < ε/2 を満たす N を取る（ε ではなく ε/2 で取るのがポイント）
  obtain ⟨N, hN⟩ := exists_pow_lt_of_lt_one h_half (by norm_num : (1 : ℝ)/2 < 1)
```

```text
ε : ℝ
hε : 0 < ε
h_half : 0 < ε / 2
N : ℕ
hN : (1/2)^N < ε / 2
⊢ ∃ N, ∀ m ≥ N, ∀ n ≥ N, dist ((1/2)^m) ((1/2)^n) < ε
```

まだゴールには存在量化が残っています。次の `refine ⟨N, ...⟩` で、今取り出した `N` を証人として渡します。

`hN : (1/2)^N < ε/2` という仮定が手に入りました。後で `(1/2)^N + (1/2)^N < ε/2 + ε/2 = ε` という着地ができます。

**ステップ③：`calc` ブロックで距離を評価し `ε` へ着地する**

```lean:断片
  refine ⟨N, fun m hm n hn => ?_⟩
  calc dist ((1 / 2 : ℝ) ^ m) ((1 / 2) ^ n)
      = |(1 / 2 : ℝ) ^ m - (1 / 2) ^ n| := Real.dist_eq _ _
    _ ≤ (1 / 2 : ℝ) ^ m + (1 / 2) ^ n := by
      apply abs_sub_le_iff.mpr
      constructor <;> linarith [pow_nonneg (by norm_num : (0 : ℝ) ≤ 1 / 2) m,
        pow_nonneg (by norm_num : (0 : ℝ) ≤ 1 / 2) n]
    _ ≤ (1 / 2 : ℝ) ^ N + (1 / 2) ^ N :=
      add_le_add (pow_le_pow_of_le_one (by norm_num) (by norm_num) hm)
        (pow_le_pow_of_le_one (by norm_num) (by norm_num) hn)
    _ < ε / 2 + ε / 2 := add_lt_add hN hN
    _ = ε := by ring

-- 上のCauchy性にℝの完備性を組み合わせると、極限の存在が得られる。
theorem geometric_has_limit :
    ∃ L : ℝ, Tendsto (fun n : ℕ => (1 / 2 : ℝ) ^ n) atTop (nhds L) :=
  cauchySeq_tendsto_of_complete geometric_cauchy
```

:::message
**💡 `calc` ブロックの読み方**

`calc` は「不等式の連鎖」を書くブロックです。各ステップで：
- `= ...` は等式
- `≤ ...` は以下
- `< ...` は未満

を順に並べ、最終的な不等式を組み立てます。各行の `:=` の右側で、その行に書いた等式・不等式の証明を与えます。`calc` はこれらを推移性でつなぐ構文です。InfoViewには、カーソル位置に対応した局所的な証明義務が表示されます。
:::

:::message
**🔍 不等式の連鎖とゴールの違い**

`refine ⟨N, fun m hm n hn => ?_⟩` の後には、`m,n ≥ N` の下で距離が `ε` 未満というゴールが残ります。`calc` の数学的な流れは、絶対値で距離を表し、各冪を `(1/2)^N` で抑え、`hN` を2回使って `ε` 未満と示すことです。

各行を書くたびに全体のゴールが右辺へ書き換わるわけではありません。例えば `abs_sub_le_iff.mpr` を使う箇所では、その行の絶対値の不等式が証明対象です。最後の等式 `ε / 2 + ε / 2 = ε` は `ring` で示します。
:::

## 9.6 完備化 ──── 「穴を埋める」操作

### Cauchy列による実数の構成

有理数のCauchy列 $(a_n)$ と $(b_n)$ を、差が0へ近づくときに同一視します。元の空間内に極限があることを先に仮定する必要はありません。有理数の言葉だけで書くなら、同値関係は

$$
(a_n)\sim(b_n)\iff
\forall\varepsilon\in\mathbb{Q},\ \varepsilon>0\Rightarrow
\exists N,\ \forall n\geq N,\ |a_n-b_n|<\varepsilon
$$

です。この同値類から実数を構成できます。

### Mathlibの一般の完備化と延長

`UniformSpace.Completion X` は一様空間の一般の完備化です。その実装はCauchyフィルターと分離商を使います。`Real` のCauchy列による構成と定義上まったく同じ型というわけではありません。

```lean:完成例・確認コマンド
import Mathlib

open Filter Topology

#check UniformSpace.Completion
#check Rat.uniformContinuous_coe_real
#check UniformSpace.Completion.extension
#check UniformSpace.Completion.extension_coe
#check UniformSpace.Completion.extension_unique
#check CompareReals.compareEquiv

-- 距離空間の完備化から、完備距離空間への一意な一様連続拡張。
theorem completion_extension_unique (X Y : Type*) [MetricSpace X] [MetricSpace Y]
    [CompleteSpace Y] (f : X → Y) (hf : UniformContinuous f) :
    ∃! g : UniformSpace.Completion X → Y,
      UniformContinuous g ∧ ∀ x : X, g (x : UniformSpace.Completion X) = f x := by
  refine ⟨UniformSpace.Completion.extension f, ⟨?_, ?_⟩, ?_⟩
  · exact UniformSpace.Completion.uniformContinuous_extension
  · exact UniformSpace.Completion.extension_coe hf
  · intro g hg
    exact (UniformSpace.Completion.extension_unique hf hg.1
      (fun x => (hg.2 x).symm)).symm
```

`Completion.extension f` の型は、通常の関数型 `Completion X → Y` です。宣言そのものに「一様連続写像の型」や一意性が組み込まれているわけではありません。上の証明では、次の3つを別々の定理から得ています。

1. `uniformContinuous_extension`：完備な値域への延長の一様連続性。
2. `extension_coe hf`：元の写像 `f` が一様連続なら、元の点上で値が一致すること。
3. `extension_unique`：同じ値を持つ一様連続な延長との一意性。

これにより、距離空間 $X$ から完備距離空間 $Y$ への一様連続写像には、一意な一様連続延長があると証明しています。一般の一様空間を値域にする場合は、完備性に加えて分離条件も確認してください。Mathlibのこの一意性の定理は `[T0Space Y]` を要求し、上の例では `[MetricSpace Y]` から得られます。距離空間からその完備化への標準写像は等長埋め込みです。

なお、`Rat.uniformContinuous_coe_real` は有理数から実数への写像の**一様連続性だけ**を述べます。完備化との一様同型を確認する別の宣言が `CompareReals.compareEquiv` です。その定義域 `CompareReals.Bourbakiℝ` は、絶対値から一様構造を入れた有理数の型を完備化したものです。この比較と実数の構成は、固定版の [CompareReals.lean](https://github.com/leanprover-community/mathlib4/blob/5c8398df528176d9c87ccd9226ba8f7c8852d59c/Mathlib/Topology/UniformSpace/CompareReals.lean) で確認できます。

一般的な設計の背景は、Mathlib公式教材 [Mathematics in Lean の位相の章](https://leanprover-community.github.io/mathematics_in_lean/C11_Topology.html) にも説明されています。掲載コードのAPIは、本書に固定した版で確認しています。

## 章末練習問題

:::message
**📝 理解度チェック**

 **問1（概念）**

次の数列が Cauchy 列かどうかをε-N の言葉で説明してください。

- (a) $a_n = \dfrac{1}{n}$（$n\geq 1$、$\mathbb{R}$ 上）
- (b) $a_n = (-1)^n$（$\mathbb{R}$ 上）
- (c) $a_n = \sum_{k=1}^{n} \dfrac{1}{k}$（調和級数の部分和、$\mathbb{R}$ 上）

:::details ヒントを見る

(a) は「収束列は Cauchy 列」から。(b) は「振動する数列はε=1で Cauchy 条件が破れる」ことを確認。(c) は調和級数が発散することから Cauchy 条件が破れる区間を見つけます。
:::

:::details 解答を見る

**(a) $a_n = 1/n$：Cauchy 列 ✓**

$\varepsilon > 0$ を任意に取る。$N > 2/\varepsilon$ となる $N$ を選べば、$m, n \geq N$ のとき：

$$|a_m - a_n| = \left|\frac{1}{m} - \frac{1}{n}\right| \leq \frac{1}{m} + \frac{1}{n} \leq \frac{2}{N} < \varepsilon$$

（実際 $a_n \to 0$ なので収束列であり、収束列は Cauchy 列です。）

**(b) $a_n = (-1)^n$：Cauchy 列でない ✗**

$\varepsilon = 1$ を取ると、任意の $N$ に対して $m = 2N$（偶数）、$n = 2N+1$（奇数）を選べば：

$$|a_m - a_n| = |1 - (-1)| = 2 > 1 = \varepsilon$$

**(c) 調和級数の部分和：Cauchy 列でない ✗**

$\varepsilon = 1/2$ を取ると、任意の $N \in \mathbb{N}$ に対して $M=\max(N,1)$ と置き、$m=M$、$n=2M$ を選べば：

$$|a_{2M} - a_M| = \sum_{k=M+1}^{2M} \frac{1}{k} \geq \sum_{k=M+1}^{2M} \frac{1}{2M} = \frac{M}{2M} = \frac{1}{2} = \varepsilon$$

$M\geq1$ なので、ここで0による除算は起こりません。

（「調和級数は発散する」という古典的な論証の核心がここにあります。）
:::

:::details 別解を見る

(a) をより簡潔に：

```lean:完成例・確認コマンド

    tendsto_const_nhds.div_atTop tendsto_natCast_atTop_atTop
  exact h.cauchySeq
```

Leanの実数の除算では `1 / 0 = 0` です。この列は `n=0` の項も持ちますが、最初の有限個の項を変えても極限やCauchy性は変わりません。
:::


`Filter.Tendsto.cauchySeq` は「収束列は Cauchy 列」という定理です。完備性（`[CompleteSpace X]`）は**不要**です。

**なぜ完備性が不要か：** 収束先 $L$ が既知（`nhds L` として明示されている）だからです。$|a_m - a_n| \leq |a_m - L| + |L - a_n|$ と三角不等式で、収束の定義から直接 Cauchy 条件が導けます。完備性は逆方向（「行き先不明の Cauchy 列が収束先を持つ」）の保証に必要です。

:::message
**📝 第9章 つまずきポイントQ&A**

**Q1. Cauchy 列と収束列は何が違うのですか？**
→ 収束列は「行き先（極限）が存在する」ことを言います。Cauchy 列は「列の要素同士がどんどん近づく」だけで、行き先が空間の中にあるかを問いません。完備空間では「Cauchy列である」と「極限が存在する」が同値です（`cauchySeq_iff_tendsto`）。極限の一意性には分離条件も必要で、本章の距離空間では満たされています。

**Q2. `CompleteSpace` はいつ使えばよいですか？**
→ 「Cauchy 列が収束する」ことを使いたいときです。`cauchySeq_tendsto_of_complete` が `[CompleteSpace α]` を仮定として Cauchy 列の収束先を取り出してくれます。`ℝ` や `ℂ` は `CompleteSpace` のインスタンスが Mathlib に登録されています。

**Q3. `CauchySeq` の定義を教えてください**
→ `CauchySeq a ↔ Cauchy (Filter.atTop.map a)` です。つまり「添字 `n` を大きくしたときの列の像が Cauchy フィルターを生成する」という意味です。実用上は `Metric.cauchySeq_iff` で ε-N による言い換えが使えます。

**Q4. `ℝ` が完備であることは証明が必要ですか？**
→ Mathlib に `instance : CompleteSpace ℝ` が登録されているので、使うだけで証明は不要です。Mathlibはその証明を既に持っています。構成まで確認する場合は、固定版の `Real` が有理数のCauchy列を使っていることに注意してください。

**Q5. 不完備な空間の例を Lean で扱えますか？**
→ 有理数 `ℚ` は不完備です。`√2` に収束するような `ℚ` の Cauchy 列を作れますが、`ℚ` 上に収束先はありません。Leanで非完備性そのものを証明するなら `¬ CompleteSpace ℚ` を示す必要があります。インスタンス探索の失敗だけでは、その否定の証明にはなりません。
:::
