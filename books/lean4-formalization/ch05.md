# 第5章：次元定理を使う 〜仮定の確認から完成例まで〜

紙に書いた次元等式をLeanへ移すとき、線形写像・ベクトル空間・有限次元性をどう表すかが課題になります。本章ではMathlibの既存の次元定理を使って、目的の等式を導きます。一般の次元定理そのものを最初から再証明する章ではありません。

完成例は本書の固定環境で確認しています。意図したエラー例と `sorry` のある骨格は別ファイルで実行してください。連結が必要なコードには順序を記し、表示したゴールや型は説明用の要約とします。

## 5.0 本章のゴール

到達するコードを先に見ます。仮定を明示し、既存定理を取り出して、等式の向きを整えます。

```lean:完成例・確認コマンド
import Mathlib

-- Mathlibの次元定理を適用し、等式の向きと加算の順を揃える。
theorem dimension_theorem_preview {K V W : Type*} [Field K]
    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    Module.finrank K V = Module.finrank K (LinearMap.ker f) +
      Module.finrank K (LinearMap.range f) := by
  have key := LinearMap.finrank_range_add_finrank_ker f
  omega
```

`key` が既存の次元定理の結論です。`omega` は自然数の等式について、左右と加算の順序を揃えます。次元に関する数学的な内容は `key` の出典で証明されています。

## 5.1 数学的準備：核・像・次元

体 $K$ 上の有限次元ベクトル空間 $V$ と、$K$ 上のベクトル空間 $W$、線形写像 $f:V\to W$ を考えます。$W$ 自体の有限次元性は仮定しません。示したい式は

$$
\dim_K V=\dim_K(\ker f)+\dim_K(\operatorname{Im}f)
$$

です。核は $\ker f=\{v\mid f(v)=0\}$、像は $\{f(v)\mid v\in V\}$ です。線形性は加法と $K$ によるスカラー倍を保存することを意味します。

```lean:完成例・確認コマンド
import Mathlib

-- LinearMap の定義を覗く
#print LinearMap
```

`LinearMap` は関数のデータと、加法・スカラー倍を保存する証明を持ちます。Mathlibの一般形には半線形写像も含まれるため、`#print` の全出力はこの説明より一般的です。本章では同じ体 $K$ 上の線形写像 `V →ₗ[K] W` を使います。

```lean:完成例・確認コマンド
import Mathlib
section
variable {K V W : Type*} [Field K] [AddCommGroup V] [Module K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W)
#check f
#check f.ker
#check f.range
end
```

同じ実数上の写像でも、実数スカラーに関する線形性と有理数スカラーに関する線形性は異なります。`[K]` はどのスカラーに対する線形性かを指定しています。

| 数学の概念 | Leanでの表現 |
|---|---|
| 体 $K$ | `[Field K]` |
| $K$ 上のベクトル空間 $V$ | `[AddCommGroup V] [Module K V]` |
| 核・像 | `f.ker : Submodule K V`、`f.range : Submodule K W` |
| 自然数値の次元 | `Module.finrank K V` |
| $V$ の有限次元性 | `[FiniteDimensional K V]` |

`f.ker` は部分空間のデータです。`Module.finrank K (LinearMap.ker f)` では、その部分空間に属する元の型へ自動変換されます。表示中の `↥` はこの型への変換を表します。

`finrank` は非計算的に定義されており、有限次元性は「次元をそのまま実行計算できる」という意味ではありません。自然数値の `finrank` と、基数値の `Module.rank` を区別します。無限次元にも基数値の次元定理がありますが、本章は有限次元の仮定を使った自然数値の定式化です。

*図5-1：有限次元の場合の対応です。最下段のMathlib定理は像の次元＋核の次元の順なので、本文では加算の順番を揃えています。*

## 5.2 `sorry` で課題を明示する

まず確認用に、核と像の有限次元性、次元等式の3つを課題として置きます。

```lean:未完成の骨格・練習問題
import Mathlib

-- 未完成の演習。確認用の補題2つと、次元等式の穴を置く。
theorem dimension_theorem {K V W : Type*} [Field K]
    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    Module.finrank K V = Module.finrank K (LinearMap.ker f) +
      Module.finrank K (LinearMap.range f) := by
  have h_ker : FiniteDimensional K (LinearMap.ker f) := sorry
  have h_range : FiniteDimensional K (LinearMap.range f) := sorry
  sorry
```

この骨格は未完成です。通常の設定では `sorry` の警告が出ます。警告をエラーとして扱う本書の完成例用ビルドには混ぜません。型検査が通っても、穴を埋められる保証にはなりません。

`h_ker` と `h_range` は数学的な前提の理解を確認するための補題です。最終的に既存の次元定理を適用するコードでは、これらを局所的な `have` として書く必要はありません。型クラスの探索が必要なインスタンスを補います。

`have 名前 : 型 := 証明` の形は、次の小さな完成例で確認できます。

```lean:完成例・確認コマンド
import Mathlib
-- have の名前・型・証明を、完成した小さい例で確認する。
theorem have_example (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  have h_ab : a ≤ b := h1
  exact le_trans h_ab h2
```

`h_ab` は後続の証明で使える局所的な事実です。証明ができていない事実を `sorry` で置いた場合は、それに依存する結論も未完成になります。

## 5.4 既存の定理を探す

核と像の有限次元性を、それぞれ単独の補題として調べます。

```lean:完成例・確認コマンド
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    FiniteDimensional K (LinearMap.ker f) := by

```

`exact?` の提案は版や文脈に依存します。次は、固定版で使える補題を明示した完成例です。

```lean:完成例・確認コマンド

theorem kernel_finite {K V W : Type*} [Field K]
    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    FiniteDimensional K (LinearMap.ker f) :=
  FiniteDimensional.finiteDimensional_submodule f.ker
```

同様に、像の有限次元性も検索します。

```lean:完成例・確認コマンド
    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    FiniteDimensional K (LinearMap.range f) := by

```

補題名を明示する場合は次のように書けます。

```lean:完成例・確認コマンド

    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    FiniteDimensional K (LinearMap.range f) :=
  Module.Finite.range f
```

次元等式そのものに進むときは、有限次元性の証明だけでは足りません。必要なのは核と像の次元を結び付ける定理です。検索が難しい場合は、コード、エラー、数学的意図にLeanとMathlibの版も添えてAIに相談し、提案された名前を実際に確認します。探索が失敗したことは、定理が存在しないことの証明ではありません。

```lean:完成例・確認コマンド
import Mathlib
#check @LinearMap.finrank_range_add_finrank_ker
-- finrank K ↥(LinearMap.range f) + finrank K ↥(LinearMap.ker f) = finrank K V
```

この定理の結論は、型引数を省略すると次の形です。

```text
Module.finrank K (LinearMap.range f) +
  Module.finrank K (LinearMap.ker f) = Module.finrank K V
```

核と像の有限次元性は、インスタンス探索によっても得られます。

```lean:完成例・確認コマンド
    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    FiniteDimensional K (LinearMap.ker f) := by
  infer_instance
```

```lean:完成例・確認コマンド
import Mathlib

-- 像も、始域の有限次元性からインスタンス探索できる。
theorem range_finite_inferred {K V W : Type*} [Field K]
    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    FiniteDimensional K (LinearMap.range f) := by
  infer_instance
```

これらは確認用の補題です。次元等式を示すには、次の既存定理を使います。

```lean:完成例・確認コマンド
import Mathlib
#check @LinearMap.finrank_range_add_finrank_ker
```

以下の2ブロックは、一つの証明として続けて置いてください。

```lean:断片
import Mathlib

-- 次の omega までを一つの証明として連結する。
theorem dimension_in_steps {K V W : Type*} [Field K]
    [AddCommGroup V] [Module K V] [FiniteDimensional K V]
    [AddCommGroup W] [Module K W] (f : V →ₗ[K] W) :
    Module.finrank K V = Module.finrank K (LinearMap.ker f) +
      Module.finrank K (LinearMap.range f) := by
  have key := LinearMap.finrank_range_add_finrank_ker f
```

`have key` の後のゴールは、型クラスの引数を省略すると次の形です。

```text
key : finrank K (range f) + finrank K (ker f) = finrank K V
⊢ finrank K V = finrank K (ker f) + finrank K (range f)
```

自然数の加法について、左右と順序を揃えます。

```lean:断片
  omega
```

これで次元等式の証明が閉じます。`omega` が次元定理そのものを発見・証明したわけではなく、`key` から導ける算術的な等式を処理しています。

| この証明の段階 | 役割 |
|---|---|
| 型クラスの前提を揃える | 体・ベクトル空間・始域の有限次元性を指定する |
| `have key := LinearMap.finrank_range_add_finrank_ker f` | 既存の次元定理を適用する |
| `omega` | `key`から加算の順番と等式の向きを揃える |
| 完成したファイルを検査する | エラー・警告と公理依存を確認する |

## つまずきポイントQ&A

**Q1. `V →ₗ[K] W` が解釈できません。**
必要な型クラスを、写像の引数より前に宣言しているか確認します。エラーに出た構造が現在の前提から得られるかも調べます。

**Q2. `have` と `letI` は同じですか。**
`have` は局所的な事実に名前を付けます。得られた値を局所インスタンスとして使わせたい場合には `letI` や `haveI` を使います。本章の核・像の有限次元性は既存のインスタンスから得られるため、主定理で登録し直す必要はありません。

**Q3. 有限次元の仮定を外すと、次元定理は偽ですか。**
本章の適用ではその仮定が必要ですが、APIの適用失敗だけで数学的な偽を結論してはいけません。基数値の次元には無限次元も扱う一般化があります。`finrank` は有限次元のときの自然数値の次元として解釈します。

**Q4. `intro` の後のゴールが分かりません。**
`∀ x, ...` や `P → Q` に対し、`intro` は変数や仮定を導入します。元のゴールと導入後の文脈を比較してください。エディタの取り消しで戻して見比べることもできます。

**Q5. `obtain` は何をしていますか。**
`h : A ∧ B` に対する `obtain ⟨hA, hB⟩ := h` は連言を分け、`h : ∃ x, P x` に対する `obtain ⟨x, hx⟩ := h` は存在する元とその性質を取り出します。

## このパートで確認したこと

命題と証明項を区別すること、必要な構造を型クラスで明示すること、定理の型を読み、意図した数学へ適用することを学びました。`sorry` で切り分けた課題は、完成した証明に置き換えて検証します。この進め方は、次の連続性・距離空間のパートでも使います。
